# 스트레스 예측 모델 검증 보고서 V2

## 결론

기존 V1~V4 실험은 같은 `KFold(5)` Seed를 반복해서 모델 구조, 분위수와
블렌드 비율 선택에 사용했기 때문에 CV 선택 과적합 위험이 있었다. 이를
보완하기 위해 중복 입력 행을 같은 Fold에 묶은
`StratifiedGroupKFold(5)`와 처음 사용하는 Audit Seed 3개로 재검증했다.

V3가 Development와 Audit 모두에서 가장 낮은 평균 MAE를 기록했고 Audit
Seed 3개에서 모두 V1을 이겼다. 그러나 Audit 쌍대 Bootstrap 95% 신뢰구간이
0을 포함하므로, 현재 증거만으로 V3를 확실한 개선 모델로 승격하지 않는다.

## 검증 설계

- 데이터: Train 3,000행만 사용했다. Test 데이터는 읽거나 분석하지 않았다.
- Splitter: 타깃을 10개 분위 구간으로 나눈 `StratifiedGroupKFold(5)`
- Group: 입력 피처가 완전히 같은 행은 동일 Fold에 배정
- Development Seed: `42`, `2026`, `3407`
- 신규 Audit Seed: `104729`, `130363`, `155921`
- 비교 조건: 후보별 완전히 동일한 Fold와 모델 Seed `42`
- 지표: 평균 MAE, Seed 승률, V1 대비 행 단위 쌍대 오차 차이,
  그룹 Bootstrap 95% 신뢰구간

Train에는 완전히 같은 입력을 가진 행이 12개(6개 그룹) 있었으며, 같은 입력
그룹 안에서 서로 다른 Target을 가진 사례는 없었다. 모든 Fold는 600행이고
각 타깃 분위 구간은 60행씩 포함되었다.

## 해석

V3는 가장 유망하지만 Audit 신뢰구간이 0을 아주 조금 포함한다. 즉 평균값의
방향은 좋으나 데이터가 다시 뽑혔을 때 개선이 사라질 가능성을 아직 배제할 수
없다. V2는 새 CV에서도 좋아 보였지만 실제 Public 점수는 V1보다 나빴다.
이 사례는 Train 분할 검증이 Public/Test 분포를 완벽히 대변하지 못하며, 작은
CV 차이를 리더보드 개선으로 단정하면 안 된다는 직접적인 증거다.

따라서 현재 운영 결론은 다음과 같다.

1. ExtraTrees를 핵심 모델로 유지한다.
2. 새 후보는 Development에서만 설계하고 Audit 확인은 제한한다.
3. Audit 평균 개선, Seed 2/3 이상 승리와 Bootstrap 상한 0 이하를 모두
   만족할 때만 강한 제출 후보로 승격한다.
4. V14처럼 강한 ExtraTrees 예측을 대부분 유지하면서 상관이 낮은 보조 모델을
   1~10%만 섞는 후보를 동일 프로토콜에서 비교한다.
5. Public 점수는 최종 확인 수단이지 블렌드 비율 선택 도구로 사용하지 않는다.

## 재현 명령

```powershell
.\.venv\Scripts\python.exe robust_validation_v5.py --data-dir /data --stages development audit --n-estimators 1200 --results-dir results\full_validation_v5
```

현재 저장된 Development와 Audit은 실행 시간을 나누기 위해 각각 별도
디렉터리에 생성했으며, 모델 설정과 검증 로직은 동일하다.
